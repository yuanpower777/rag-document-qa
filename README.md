# 智能文档问答助手（RAG）

一个基于 **RAG（Retrieval-Augmented Generation，检索增强生成）** 的文档问答应用：
上传你自己的文档后，用自然语言提问，系统先从文档中检索相关片段，再让大模型**只依据这些片段**
生成回答，并标注答案出处。

命令行和网页两种使用方式，核心检索逻辑不依赖 FAISS / PyTorch 等重型库，在普通笔记本上即可跑通。

---

## 一、解决什么问题

把大模型直接当成"文档问答"来用，会遇到三个问题：

| 问题 | 具体表现 |
|---|---|
| **不知道你的私有文档** | 大模型只见过公开语料，你上传的课程资料、产品手册、制度文件它完全不了解 |
| **会编造（幻觉）** | 不知道答案时它倾向于"编一个看起来合理的"，而且编得很像真的，很难分辨 |
| **无法溯源** | 就算答对了，你也不知道这句话是从哪来的，无法核对，也无法追责 |

本项目用 RAG 的思路解决：**不把问题直接丢给大模型，而是先在文档里检索出相关片段，
把片段连同问题一起交给大模型，并在 Prompt 层强制要求"只依据给定片段回答、无法回答就说不知道、
必须标注引用编号"。** 这样答案有据可查、可追溯到原文段落，幻觉显著减少。

典型适用场景：课程资料/论文问答、产品手册与制度文件查询、内部知识库检索、技术文档助手。

---

## 二、主要功能

1. **多格式文档加载**：支持 `.txt` / `.md` / `.pdf` / `.docx`（Word 正文与表格均可解析）
2. **文本切分**：按字符窗口切分，优先在换行、句号等自然边界断开，避免把句子切碎；支持重叠窗口
3. **文本向量化**：两种后端可选
   - 本地兜底方案（默认）：hashing + 中文字符二元组特征，零额外依赖、无需 embedding 额度
   - 真实语义 embedding：配置 `EMBED_MODEL` 后调用 OpenAI 兼容的 embedding 接口
4. **向量检索**：向量 L2 归一化后用 numpy 做余弦相似度检索，取 Top-K 相关片段（零编译依赖）
5. **受约束的答案生成**：把召回片段组装成带编号的 Prompt，通过系统提示词约束模型
   - 只依据参考资料回答，资料中没有就回答"资料中未提及"
   - 回答中标注 `[1] [2]` 引用编号，便于回溯原文
   - `temperature=0.2`，降低随机性
6. **答案溯源**：网页界面可展开查看每条回答引用的原文片段及其相似度分数
7. **网页界面**：Streamlit 实现，支持多文件上传建索引、参数实时调节、流式输出、多轮对话
8. **批量评测脚本**：`run_eval.py` 可对一整套测试题跑检索评测，统计召回命中率，用于对比不同参数

## 三、安装方法

### 环境要求

- Python 3.10+（开发环境为 3.12 / 3.14）
- 一个大模型 API Key（默认使用 DeepSeek，任何 OpenAI 兼容接口都可以）

### 1. 获取代码并创建虚拟环境

```bash
git clone https://github.com/<your-name>/<repo-name>.git
cd <repo-name>

python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

依赖仅四项：`openai`（调用大模型）、`streamlit`（网页界面）、`numpy`（向量检索）、
`pypdf` + `python-docx`（文档解析）。

### 3. 配置 API Key

```bash
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxx"

# Windows CMD
set DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx

# macOS / Linux
export DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxx"
```

> 注意：未配置 Key 时，**检索功能仍然可用**（命令行会正常输出召回片段），只是生成回答会提示失败。

### 4. 可选：配置语义 embedding（推荐，检索质量更好）

默认使用本地兜底向量化（不是语义模型，检索能力弱于真实 embedding）。
如果你有 OpenAI / 智谱 / 通义等提供的 embedding 接口，配置以下变量即可切换：

```bash
export EMBED_MODEL="text-embedding-3-small"     # 留空则用本地兜底方案
export LLM_BASE_URL="https://api.openai.com/v1" # 默认 https://api.deepseek.com/v1
export LLM_MODEL="gpt-4o-mini"                  # 默认 deepseek-chat
export EMBED_API_KEY="sk-xxxx"                  # 不设置则复用 DEEPSEEK_API_KEY
```

## 四、使用方法

### 方式一：命令行（最快验证）

```bash
# 交互式问答（可连续提问，输入 exit 退出）
python cli.py data/sample.txt

# 提问一次后退出
python cli.py data/sample.txt -q "金卡会员有什么权益？"

# 指定召回条数
python cli.py data/sample.txt -q "退货政策是什么？" -k 3

# 支持多个文档同时建索引
python cli.py data/sample.txt 你的资料.docx
```

命令行会先打印召回的片段及相似度分数，再打印模型生成的答案。

### 方式二：网页界面

```bash
streamlit run app.py
```

浏览器打开 `http://localhost:8501`，然后：

1. 在页面上传 `.txt` / `.md` / `.pdf` / `.docx` 文档（可多选）
2. 点击「建立索引」，等待切分与向量化完成
3. 在底部输入框提问，回答会流式输出，并展开「来源」查看引用的原文片段

左侧边栏可实时调整 `chunk_size`（切分粒度）与 `Top-K`（召回条数），用于对比效果。

### 方式三：零依赖离线自测

不需要 API Key、不需要联网，只验证「切分 + 向量化 + 检索」链路是否正常：

```bash
python selftest.py
```

### 方式四：批量评测

对整套测试题跑检索评测，统计召回命中率（不调用大模型，不需要 Key）：

```bash
python run_eval.py data/sample.txt
python run_eval.py data/机器学习实验报告-评测语料.txt --chunk-size 800 --top-k 4
python run_eval.py 你的文档.docx --ask        # 额外调用大模型生成答案
```

结果会写入 `eval_result.json`，包含每题召回到的片段与命中情况，便于逐题分析。

## 五、输入输出示例

> 说明：示例 1、3 中的**检索结果与相似度分数**是真实运行输出；
> **大模型生成的答案文本**因每次调用措辞都会不同（且依赖你自己的 API Key），
> 这里给出的是代表性格式示例，用于说明输出的组织方式。

### 示例 1：命令行问答

**输入**（知识库为仓库内置的示例文档 `data/sample.txt`，内容是一份电商售后与会员权益手册）：

```bash
python cli.py data/sample.txt -q "金卡会员有什么权益？"
```

**输出**：

```
[索引] data/sample.txt -> 3 个文本块

--- 检索到的片段 ---
[1] data/sample.txt score=0.193 :: 退换货运费由平台承担。 2. 无理由退货的往返运费由买家承担，会员可享受每月 3 次免运费退货权益...
[2] data/sample.txt score=0.092 :: 星海商城 售后服务与会员权益手册（示例文档） 一、退换货政策...
[3] data/sample.txt score=-0.027 :: 小时内发送至预留邮箱。 3. 增值税专用发票需要提供公司名称、纳税人识别号、开户行及账号信息...

--- 回答 ---
金卡会员的权益包括 [1]：
1. 每月 3 次免运费退货；
2. 专属客服；
3. 生日双倍积分。

（升级条件：累计消费满 8000 元可升级为金卡会员 [1]。）
```

可以看到：回答中的每一条都标注了引用编号 `[1]`，可以回到上面检索到的片段中核对原文。

### 示例 2：未配置 API Key 时的行为

检索部分照常工作，只有生成环节报错——这也是判断问题出在「检索」还是「生成」的快速方法：

```
$ python cli.py data/sample.txt -q "退货政策是什么？"
[索引] data/sample.txt -> 3 个文本块

--- 检索到的片段 ---
[1] data/sample.txt score=0.234 :: ...
--- 回答 ---
生成失败：未配置 API Key，请设置环境变量 DEEPSEEK_API_KEY
```

### 示例 3：防幻觉表现（资料中没有的问题）

**输入**：

```bash
python cli.py data/sample.txt -q "星海商城支持比特币支付吗？"
```

**输出**：模型会回答「资料中未提及」相关表述，而不是编造一段支付政策——
这正是系统提示词约束的作用。

### 示例 4：批量评测结果

评测语料为 `data/机器学习实验报告-评测语料.txt`（约 7200 字），
测试题为 `test_questions.json` 中的 20 道，覆盖事实抽取、数字核对、跨段归纳，
以及 2 道用于检测编造的"兜底题"。对比不同参数的检索召回命中率：

| chunk_size | 切分块数 | Top-K=3 | Top-K=4 | Top-K=6 |
|---|---|---|---|---|
| 300 | 39 | 44% | 56% | 67% |
| 500 | 19 | 61% | 78% | 83% |
| 800 | 12 | 61% | 78% | 94% |

> 统计口径：该题所有期望关键词是否**全部**出现在召回的 Top-K 片段中。
> 兜底题（资料中无答案）不计入命中率。

**关于结果的说明（重要）**：命中率随切分粒度与召回数量单调上升，但这**不代表参数越大越好**：

- **口径偏差**：文本块越大，越容易"顺带包含"期望关键词，指标会虚高；
- **真实代价**：`chunk_size=800 + Top-K=6` 会把数千字原文塞进 Prompt，冗余多、更慢、更贵；
- **实际短板**：细粒度数值（如某个字段的取值范围）在大块中容易被淹没，这类问题反而更容易漏。

因此本项目的默认配置取 `chunk_size=500, Top-K=4` 作为平衡点；如果只针对单份文档追求最高召回，
可以调到 `800/6`。

> 补充：同一份内容以 Word 原文件（`.docx`）作为知识库时，因为表格与换行的解析结果不同、
> 切分块数更少（7～13 块），上述配置的命中率会略高（`500/4` 为 72%，`800/4` 为 94%）。
> 这说明**切分结果对文档格式很敏感**，也是后续改进方向之一。

## 六、项目结构

```
.
├── app.py                 Streamlit 网页界面
├── cli.py                 命令行问答入口
├── rag.py                 核心模块：加载 / 切分 / 向量化 / 检索 / 生成
├── run_eval.py            批量检索评测脚本
├── selftest.py            零依赖离线自测（不联网、不需要 Key）
├── test_questions.json    20 道测试题（含期望关键词与答案要点）
├── requirements.txt       依赖清单
├── LICENSE                MIT License
└── data/
    ├── sample.txt                          示例知识库文档（电商售后与会员权益手册）
    └── 机器学习实验报告-评测语料.txt        批量评测所用的知识库文本
```

### 核心流程（`rag.py`）

```
文档 → load_text() 解析
     → split_text() 切分（按自然边界，可重叠）
     → embed() 向量化（本地兜底 / 真实 embedding 接口）
     → VectorStore 余弦相似度检索 Top-K
     → build_prompt() 组装带编号的参考资料
     → generate() 调用大模型生成带引用的回答
```

## 七、已知限制

- **默认向量化不是语义模型**：本地兜底方案基于词形特征（hashing + 字符二元组），
  同义改写、跨语言提问的召回效果有限。配置 `EMBED_MODEL` 使用真实 embedding 后明显改善。
- **索引只在内存中**：每次启动都需要重新建索引，文档量大时启动较慢。生产环境应换用
  持久化向量数据库（如 FAISS、Chroma、Milvus）。
- **数据量级**：numpy 全量点积在数千片段量级没问题，超过十万级需要换专用向量索引。
- **切分策略固定**：目前是字符窗口 + 自然边界，未做语义切分（按标题/段落结构切分）。
- **无重排序**：召回后直接取 Top-K，没有 Rerank 二次排序。

## 八、后续可改进方向

- 接入真实语义 embedding + Rerank 二次排序，提升召回精度
- 按文档结构（标题层级、表格）做语义切分，而不是固定字符窗口
- 索引持久化，避免每次重建
- 多轮对话时对历史问题做改写再检索（Query Rewriting）
- 增加引用高亮与用户反馈（点赞/点踩）做效果闭环
